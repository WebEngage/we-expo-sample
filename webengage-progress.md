# WebEngage in WE Shop — where things stand
Updated 2026-10-19 · Quick setup

## Done
- WebEngage is set up on Android and iOS: the plugin in `app.config.js`, your license (read from `WEBENGAGE_LICENSE_CODE` in `.env`), US data center, and one file, `src/analytics/WebEngageManager.ts`, that all WebEngage calls go through. It does nothing on web and in Expo Go and never throws into your code.
- The native projects were regenerated (`expo prebuild`) and `pod install` was run; the generated files carry the WebEngage keys on both platforms.
- Login and logout are reported using your account id. A restored session is identified again at launch. Guests stay anonymous.
- `email` and `City` are sent as profile details.
- Two events are tracked: `Added To Cart` and `Order Placed` (amounts in USD, no personal data in them).
- Push is set up on both platforms. Android: a push library (`expo-notifications` + `expo-task-manager`) receives pushes in the foreground, background and when closed, sends the device token on every launch, and asks for notification permission once from the home tab. iOS: Rich Push (images, carousels, action buttons) through two notification extensions that were added to `ios/`.
- In-App messages need no code; they appear when a live campaign targets the user.

## Waiting on you
- Build and run the app on a test device: `npx expo run:android` and `npx expo run:ios`. Restart Metro first if it's running. The changes only take effect in a new native build.
- On iOS, signing needs the Push capability, and the app will ask for notification permission at launch.
- Upload your push credentials in the WebEngage dashboard: the Firebase service-account JSON (same project as `google-services.json`) under Data Platform → Integrations → Push Setup, and the APNs `.p8` key with its Key ID, Team ID and bundle ID.
- Register `com.webEngage.prodSwift.NotificationService`, `com.webEngage.prodSwift.NotificationViewController` and the App Group `group.com.webEngage.prodSwift.WEGNotificationGroup` in your Apple Developer account, and set `devTeam` for local device builds (tell me your Team ID and I'll add it).
- Test push on a physical device, with the app in the foreground, in the background and fully closed.
- `google-services.json` is untracked and not git-ignored. Decide whether to commit it; it holds Firebase API keys, which are normally not secret but are yours to judge.
- Tell me what you see from the checks below.
- ⚠️ `android/` is tracked in git, so the license code now sits in `android/app/src/main/AndroidManifest.xml`. Don't stage that file (or stop tracking `android` with `git rm -r --cached android`).
- Teammates and CI: copy `.env.example` to `.env` and set `WEBENGAGE_LICENSE_CODE`.
- Debug logging is on for development builds. Make sure release builds stay quiet (`APP_VARIANT=production` for a local release build).

## How to check each piece
- **Setup:** Android: `adb logcat -d -s WebEngage` shows `Successfully Initialized`. iOS: the Xcode console shows `WebEngage SDK Initialized`. Or open Dashboard → Users → Live Users.
- **User:** log in, then find your account id under Users on the dashboard; email and City should be on the profile.
- **Events:** add a product to the cart and place an order; both events appear on the user's activity. Ask me for step-by-step.
- **Push:** register the test device on the dashboard, send a test push campaign, and try foreground, background and closed. On iOS with Rich Push, images and buttons should render. If nothing arrives: credentials, notification permission, Firebase project, then `push.mode` on iOS.
- **In-App:** create a live In-App campaign for your test user and trigger it with one of the two events.

## How to undo
- **Setup:** remove the WebEngage entries from `app.config.js` (or delete it), delete `plugins/withWebEngageAndroidExtras.js`, `src/analytics/WebEngageManager.ts` and its import and `init()` call in `src/app/_layout.tsx`, remove `.env.example` and the `.env` line in `.gitignore`, then `npm uninstall react-native-webengage webengage-expo`. `ios/` is regenerated by the next prebuild; for `android/`, `git restore -- android` (⚠️ also discards other uncommitted edits there). Rebuild afterwards.
- **User and events:** delete the `identifyUser` helper and the `WebEngageManager` calls in `src/context/AppContext.tsx`.
- **Push:** remove the `webengage-expo-push` entry and the `googleServicesFile` lines from `app.config.js`; delete `src/analytics/webengageBackgroundTask.ts`, `useWebEngageAndroidPush.ts` and `pushPermission.ts`, their import and hook call in `src/app/_layout.tsx` and the `requestPushPermissionAndOptIn` call in `src/app/(tabs)/index.tsx`; `npm uninstall webengage-expo-push` (and `expo-notifications expo-task-manager` if nothing else uses them); regenerate or restore `ios/` and `android/` as above, then rebuild.
- **Notes:** delete `.webengage/`, this file and `webengage-support-summary.md`.
- Data already sent to WebEngage stays there; removing it is done in the dashboard or through support@webengage.com.
